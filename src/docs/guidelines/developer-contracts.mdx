# Developer contracts

Code-level rules that keep the other guidelines from silently breaking. Each one is a contract between two pieces of
code, or a fix that's easy to undo by accident. Full history in
[`DESIGN.md`](https://github.com/jcaunedo/verita-ucl/blob/main/DESIGN.md).

## Pointer cursor is global

Every clickable element shows `cursor: pointer` (and `not-allowed` when disabled) through one rule in `theme.css`'s
`@layer base`, which matches real interactive elements and roles: `button`, `a[href]`, `[role="button"]`, and React
Aria's options, menu items, tabs, and links.

- Don't add `cursor-pointer` to a component. Tailwind 4 sets `cursor: default` on buttons, which is why the global rule
  exists.
- A custom clickable element (a `div` acting as a button) needs `role="button"`, plus `aria-disabled="true"` when
  disabled, or it won't get the cursor.
- A new interactive role that isn't covered: extend the selector list in `theme.css` (and its copy in `DESIGN.md`),
  never patch the one component.
- Hover every clickable element in Storybook to confirm. Deliberate exceptions: the `Sidebar` collapse rail's resize
  cursors, and `Button`'s disabled state.

## One hover token per Figma variable

`--hover-row`, `--hover`, `--icon-hover`, and `--shadow-hover-card` each map to their own Figma variable, even where two
values currently match. When they shared one token, a change meant for controls darkened every card. Add any new
hover-like token the same way: its own `:root` variable plus its `@theme inline` mapping. See
[Lists and rows](?path=/docs/guidelines-lists-and-rows--docs).

## Radius roles must be registered with `cn()`

Every component radius role in `theme.css` (`rounded-card`, `rounded-select-content`, `rounded-button-md`, …) must also
be listed in the `extendTailwindMerge` radius config in `src/lib/utils.ts`. Otherwise `tailwind-merge` doesn't know the
class, keeps an override like `rounded-3xl` next to it, and the corner radius depends on stylesheet order. Add the name
in the same change as the token.

## Font rendering is set once, on `html`

`theme.css` sets font smoothing, optical sizing, `text-rendering`, the font family, text color, and
`font-synthesis: none` on `html`, and everything inherits them, including portaled menus and consuming apps. Don't
repeat them on components, and don't add Tailwind's `antialiased` classes. Compare against Figma only in a browser with
this stylesheet loaded: without it, Inter renders a step heavier on macOS. See
[Foundations/Typography](?path=/docs/foundations-typography--docs), which also covers the no-900-weight rule.

## Expanding search animates `width`, not `layout`

`SearchField` animates its pill's `width` directly (44px ↔ 240px), with `overflow-hidden` and `rounded-full` on the same
element. Don't switch it to a `layout` animation: that scales the element with a transform and squashes the round
corners mid-way. A documented exception to the motion system's "prefer `layout`".

## Breakpoints and layout helpers

- Breakpoints are registered 1px past each frame width; use `lg:`/`max-lg:` and `mediaAbove()`
  ([Page layout](?path=/docs/guidelines-page-layout--docs)).
- Canvas gutters come only from `layoutCanvasPaddingClassName`, the sidebar's collapse behavior only from
  `useLayoutSidebar`. The gutter transition copies `enterTransition`'s timing in CSS, so update `layout-canvas.ts` if
  `enterTransition` changes.
