# Guidelines

Components tell you what each piece looks like. These guidelines tell you how the pieces behave **together on a page**:
when a card gets a button, how a list of rows is drawn, what an empty view shows, where a toast appears. Each rule was
settled with design, often after several rounds, so follow it rather than re-deciding it screen by screen.

They apply to every Verita product equally. Internal and operational tools meet the same bar for clarity, usability, and
polish as consumer screens: don't skip states, motion, or copy quality because a screen is internal.

## How each rule is written

- **Rule:** what to do, in plain language.
- **Why:** the reason, and when it was decided, so you can tell a deliberate choice from an accident.
- **For developers:** the component, prop, or helper that implements it, and what not to hand-roll.
